# Web 试听与移动端优化

## 范围与交互

1. 概览源状态：正常使用绿色圆点，异常使用红色圆点；圆点由 8px 增大为 12px，同时提供状态文字供辅助技术读取。
2. 榜单页：点击解析结果中的歌名试听单首；复用现有复选框，增加「试听已选」与「试听全部」，按榜单顺序播放。页内播放器显示当前歌曲和队列，提供播放、暂停、停止（回到开头）、上一首、下一首、进度拖动和队列跳转。自然结束后自动播放下一首，队列末尾停止。切换榜单或离开页面时释放播放器，避免后台继续播放旧榜单。失败显示原因并允许手动切歌，不无限重试。
3. 小于 960px 时，概览源状态和搜索数据源默认折叠。概览保留总数、可用和异常数量；搜索保留已选数量及简短摘要。展开后操作原有选项，折叠不改变选择。桌面保持展开。
4. 手机底部常用导航：概览、搜索、榜单、任务、设置；专辑仍可通过完整导航访问。

## 方案选择

- 直接播放平台地址：实现较少，但 HTTP 混合内容、平台请求头和来源限制可能导致浏览器无法播放。
- **推荐：同源流式试听 + 浏览器 audio 播放器。** 复用服务端已缓存曲目的地址与音频请求信息，保留 Range 请求用于拖动。通过已鉴权请求领取仅限当前曲目的临时播放地址，避免把 API Key 放进媒体 URL。无需新增播放器依赖，也不创建下载任务或归档文件。
- 先完整下载再播放：拖动稳定，但需要等待整首下载并占用额外存储，本次不采用。

## 数据与边界

- 新增独立试听模块与 API，曲目必须来自现有缓存，客户端不能指定任意代理目标。
- 播放凭据短期有效并限定曲目；过期或缓存失效后提示重新解析/重试。代理保留必要的 Content-Type、Content-Length、Content-Range 和 Accept-Ranges；停止与断开时关闭上游连接。
- 支持浏览器可解码的原始音频，不引入转码服务；平台地址失效、格式不支持时提供可理解的错误提示。
- 播放控制逻辑独立于曲目选择，试听不触发下载。
- 不修改本地 config.yaml 与已有未跟踪文件。

## 验证

- 后端：鉴权、限曲目凭据、过期、缓存失效、音频流与 Range、上游错误和连接释放。
- 播放交互：单首、多选、全选、顺序衔接、暂停恢复、停止归零、切歌、进度定位、失败重试和卸载清理。
- 浏览器：390px 手机与 1440px 桌面，检查折叠、状态颜色大小、底部榜单入口和播放器布局。
- 运行前端构建和现有后端测试。

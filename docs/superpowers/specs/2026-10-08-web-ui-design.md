- 文档状态：**原型待确认**（确认后按 P1→P3 分期动工）
- 创建日期：2026-10-08
- 技术栈：Vue 3 + Vuetify 3 + Vite + vue-router + Pinia + axios（方案 A，已选定）

## 1. 设计原则

1. **移动优先，一套代码**：不写独立移动站。PC 用侧边抽屉导航 + 数据表格；手机用底部 Tab + 卡片列表。断点按 Vuetify 默认（<960px 视为手机布局）。
2. **操作如实反映后端能力**：同步阻塞的歌单解析给长 loading；运行中任务的"取消"置灰并附原因；需重启生效的配置项打标签，不假装热更新了一切。
3. **危险操作两步走**：清理/替换/迁移等带 `dry_run` 的操作，一律"预览结果 → 确认执行"；无 dry_run 的破坏性操作（整目录删除）弹确认对话框并回显 `confirm=true` 语义。
4. **零学习成本导航**：九个页面收敛为五个一级入口，手机首屏即可触达核心闭环（搜索/下载/任务）。

## 3. 全局机制

### 3.1 鉴权与登录

- 首次访问：全屏居中卡片，仅一个"API Key"密码输入框 + "进入"按钮；提交时试调 `GET /api/v1/sources` 验证，通过则存 localStorage。
- 服务端未启用 api_key 时跳过登录页直接进。
- 任何请求收到 401 → 清空本地 key → 跳回登录页 + snackbar 提示"密钥失效"。
- 顶栏 🔑 按钮：显示当前鉴权状态，可"更换密钥/退出"。

### 3.2 通用模式

- **请求层**：axios 实例统一注入 `X-API-Key`；统一错误拦截 → snackbar（红色，显示后端 `detail` 文案）。
- **加载态**：页面级骨架屏（v-skeleton-loader）；按钮级 loading（防重复提交）。
- **空态**：每页定义空态文案 + 引导动作（如任务中心空态："还没有任务，去搜索一首歌试试" + 跳转按钮）。
- **轮询**：仅任务中心页面激活时轮询（3s），离开页面即停；专辑任务完成后自动停轮询并提示"可去归档"。
- **确认对话框**：统一组件，标题 + 后果说明 + 危险操作红色确认按钮。
- **主题**：浅色/深色跟随系统，顶栏可手动切换（存 localStorage）。

## 4. 逐页原型

### 4.1 仪表盘 `/`

**用途**：一眼看清系统健康度与在途任务。

**布局**：卡片网格（PC 三列，手机单列）：

```
[源状态]        [在途任务]        [下载目录占用]
 咪咕 ✅ 无损     3 个进行中        4.2GB / 阈值 10GB
 网易 ✅         最近完成：          [立即清理]（达阈值才亮）
 QQ   ✅ 保活中    圣诞星 ✅
 酷我 ✅          [查看全部 →]
 千千 ⚠️ 无cookie
[QQ 登录态]      [飞牛音乐]         [快捷入口]
 有效期至 xx      ✅ 已连通          [搜索][专辑][榜单][媒体库]
 剩余 41h 自动续   未配置→引导文案
```

- 数据源：新增 `GET /api/v1/system/status`（P1 后端任务）。
- 卡片点击可跳转对应页面；异常卡片用警示色并给出修复指引（如"QQ 凭证已失效，去设置页粘贴 cookies"）。

### 4.2 搜索下载 `/search`

**交互流**：输入关键词（可选源多选 chips）→ 结果列表 → 勾选 → 底部操作栏"下载 N 首" → 下载选项对话框 → 提交成功跳任务中心。

```
┌────────────────────────────────────────────┐
│ [🔍 搜索歌名/歌手____________] [源:全部▾]   │
├────────────────────────────────────────────┤
│ PC：数据表格 ☐歌名/歌手/专辑/时长/音质/源    │
│ 手机：卡片流（封面缩略图+两行文字+音质标）   │
│ ☑ 晴天 - 周杰伦 · 叶惠美 · FLAC · QQ        │
│ ☐ 晴天 - 周杰伦 · 叶惠美 · 320k · 咪咕      │
├────────────────────────────────────────────┤
│ 已选 2 首              [下载选项] [立即下载] │ ← 吸底操作栏
└────────────────────────────────────────────┘
```

**下载选项对话框**：目标库（下拉：默认库/singles）、体积上限 MB（留空=配置默认）、子目录（可选）、飞牛歌单名（选 singles 库且已配置飞牛时出现，可留空）。

- 音质徽标用颜色区分：无损=绿、320k=蓝、其他=灰。
- 超限曲在提交后被服务端剔除时，结果 snackbar 明示"已跳过 N 首超限曲目"。

### 4.3 专辑 `/albums` + `/albums/:id`

**搜索页**：搜索框 + 专辑卡片网格（封面、专辑名、艺人、年份、来源标 iTunes/网易/QQ）。

**详情页**：

```
┌────────────────────────────────────────────┐
│ [封面]  叶惠美                                │
│         周杰伦 · 2003 · 国语流行             │
│         简介（折叠展开）                      │
│         [下载整张专辑] [整表复制]             │
├────────────────────────────────────────────┤
│ CD1                                          │
│  1. 以父之名                    5:42         │
│  2. 懦夫                        3:30         │
│  ...（多碟分 CD1/CD2 分组）                  │
└────────────────────────────────────────────┘
```

- 下载提交后跳任务中心；专辑任务完成后任务卡片出现"去归档"按钮 → 归档对话框（目标库、合集 VA 开关、专辑名/艺人覆盖、overwrite）→ 执行 `archive_album` → 结果逐曲展示（成功/跳过/失败原因，失败行附"重试单曲"入口跳搜索页预填关键词）。
- 罗马音专辑名场景：详情页标题旁显示"显示名修正"小按钮（填中文名 → 下载/归档时带上覆盖参数）。

### 4.4 榜单 `/charts` + `/charts/:source/:id`

- 目录页：按源分组（网易/QQ Tab 切换），榜单卡片（名称+更新频率）。
- 曲目页：与搜索页同款列表 + "全表下载"吸底按钮 + 勾选子集下载。顶部 banner 提示"榜单解析为同步请求，约需数秒"。

### 4.5 歌单解析 `/playlist`

- 顶部：URL 粘贴框 + 源选择（默认自动识别）+ "解析"按钮。
- 解析中：整页 loading + 文案"大歌单解析较慢（同步接口），请耐心等待，勿重复提交"。
- 结果：曲目列表（同搜索页列表组件），勾选/全表下载。

### 4.6 任务中心 `/tasks`

- Tab：**进行中**（页面激活时 3s 轮询）/ **历史**（`GET /history`）。
- 任务卡片：类型标（单曲/专辑）、标题、状态徽章（pending 蓝/running 绿/success 灰/failed 红）、进度（专辑显示 x/y 首）、耗时、错误摘要（可展开）。
- 操作：pending 任务可"取消"；running 任务取消按钮置灰（tooltip"运行中任务不可中断"）；完成的专辑任务显"去归档"；失败任务显"查看详情"（展开 manifest 的逐曲 score/unmatched 原因）。
- 顶部提示条（可关闭）："服务重启后进行中的任务状态会丢失，完整记录见历史 Tab"。

### 4.7 媒体库 `/library`

- 顶部库选择 Tabs：默认库 / singles（来自 `GET /libraries`）。
- 四个操作卡片，各弹对话框、全部先 dry_run 预览：

| 操作 | 对话框字段 | 预览→执行 |
|---|---|---|
| 歌词回填 | 范围（艺人/专辑可选）、上限、源 | 预览"将为 N 首补歌词"清单 → 确认执行 |
| 曲目替换 | 艺人、专辑、曲目（支持 D-NN）、源、强制开关 | 直接执行（本身幂等，有新版才换），结果展示新旧音质对比 |
| 库内清理 | 艺人/专辑/曲目 三级 | dry_run 列出将删文件 → 确认；整艺人/整专辑删除额外勾"我知道这是整目录删除"（对应 confirm=true） |
| 单曲迁移 | 艺人范围可选 | dry_run 列出将迁移目录 → 确认 |

- 结果区统一展示受影响文件列表；飞牛用户附提示："回填/替换后需在飞牛侧触发重扫（移出再移回目录）"。

### 4.8 飞牛歌单 `/fnos` + `/fnos/:name`

- 未配置 `fnos_music`：引导页（说明 + 跳设置页）。
- 列表页：歌单卡片（名称、曲目数）+ "新建歌单"按钮（可关联任务：从任务中心挑已完成单曲任务一键建单）。
- 详情页：曲目列表 + "追加曲目"对话框（两种方式：搜索飞牛曲库勾选 / 从本服务已完成任务导入）+ 搜索框（suggest 四组下拉）。
- 不提供删除歌单/移除曲目（后端暂无此端点，ROADMAP 2j 后续项，界面上不露出）。

### 4.9 设置 `/settings`

分组手风琴（expansion panels），每个字段带"热生效"绿标或"需重启"橙标：

```
▸ 基础          线程数🟠 体积上限🟢 归档注释🟢 默认搜索源🟢
▸ 下载与存储     download_root🟠 db_path🟠（改路径类一律重启）
▸ 媒体库         library_root🟠 命名库根🟠
▸ 音源 Cookies   五源逐个可展开粘贴（密码框 + "已设置"掩码回显）🟢
▸ 清理策略       归档后清理🟢 定期清理🟢 周期/阈值/保护期🟢
▸ QQ 登录态      开关🟢 检查周期🟢 [立即刷新]按钮 + 状态回显🟢
▸ 飞牛音乐       base_url/账号/密码（掩码）/path_map 编辑🟢
▸ 安全           API Key（密码框，留空=关闭鉴权）🟢
▸ MCP 适配器     只读展示 + 提示"改后需重启 mcp 容器"🔵
```

- 保存按钮吸底；保存后 toast 汇总："已热生效 5 项；3 项需重启服务后生效"。
- 修改 API Key 且当前正在用它登录时，提示"保存后需用新密钥重新登录"。

### 4.10 视觉语言（借鉴 go-music-dl，落地为 Vuetify 配置）

对 go-music-dl Web UI 做源码级分析后，采纳以下设计语言（全部可用 Vuetify 主题/CSS 实现，不换技术栈）：

1. **主色翠绿系**：primary `#10b981`，主渐变 `linear-gradient(135deg, #34d399, #059669)`；Logo/页面主标题用渐变文字。
2. **顶部氛围光晕**：内容区顶部 600px 高三色径向渐变光晕向下渐隐（body::before 一层 CSS 即可），替代纯色背景——零成本质感提升。
3. **圆角体系**：卡片 `rounded="xl"`（16-20px）；搜索框与主按钮用全圆角胶囊（`rounded="pill"`）；hover 上浮 `translateY(-2px)` + 加深阴影。
4. **搜索页胶囊化**：搜索输入框 + 圆形渐变搜索按钮同行；源选择做成可折叠的"源卡片网格"（勾选描边变主色），替代下拉多选。
5. **曲目行可点实体**：歌手名/专辑名做成可点链接（点歌手→精确搜索、点专辑→专辑页），详情跳转零成本。
6. **列表工具 popover**：每页条数/排序等次要控件收进一个"列表工具"下拉，列表头保持清爽。
7. **任务入口徽标**：导航"任务中心"带进行中数徽标（已有），借鉴其"下载完成红点提醒"语义。
8. **保留我方优势不降级**：暗色模式（对方没有，我们保留）；不引入播放器/看板娘等娱乐化元素（我们是管理工具不是听歌应用）。
9. **反面教训**：对方 7300 行单文件原生 JS + 无组件化，我们坚持 Vue 组件化路线，只借鉴视觉与交互模式。

### 4.11 扫码登录（新增能力，借鉴 go-music-dl 交互）

**目标**：设置页 Cookies 分组里，支持扫码的平台（**网易云、QQ**；备选酷狗）行内提供"扫码"按钮，手机扫码确认后 cookies 自动回填并热生效，免除手动粘贴。QQ 扫码成功后同时重置 `qqauth` 保活种子（等同"重新粘贴 cookies"的既有语义）。

**后端新增端点**（协议按各平台公开登录流程自行实现，**不引入对方 AGPL 代码**）：

```
POST /api/v1/auth/qr/{source}          创建扫码会话 → {key, image_url 或 url}
GET  /api/v1/auth/qr/{source}?key=…    轮询状态 → {status, cookies?}
    status: waiting | scanned | success | expired | failed
```

- success 时 cookies 直接写入 `settings.sources[source]`（热应用）+ 回写 config.yaml（复用 webconfig 的 ruamel 回写），前端输入框同步回填掩码。
- QQ 成功额外触发 qqauth 种子重置，保活链路无缝接管。
- 会话态存内存（key → 状态/过期时间），不落库。

**前端交互**（状态机弹窗，对齐对方已验证的流程）：

```
┌─────────────────────────┐
│ QQ 音乐扫码登录           │
│ ┌───────────────────┐   │
│ │     [二维码]        │   │ ← 优先服务端 image_url，否则前端 canvas 自绘 URL
│ └───────────────────┘   │
│ ● 等待扫码中…            │ ← 四态配色：waiting 灰/scanned 黄/success 绿/expired 红
│ [刷新二维码]   [关闭]     │
└─────────────────────────┘
```

- 轮询 2.2s 一次、防重入，关窗/过期即停；成功后 toast + 900ms 自动关窗 + Cookie 输入框回填。
- 弹窗尺寸移动端 `max-width: 92vw`，二维码 `min(280px, 86vw)`。

**风险**：各平台登录态字段与 musicdl 所需 cookies 的对齐需实测（QQ 重点验证 musickey 可得性）；若某平台扫码拿不到有效下载态 cookies，该源降级为只保留手动粘贴。

## 5. 关键闭环走查（验收用）

1. **手机搜歌入库**：手机打开 → 登录 → 搜索"晴天" → 勾无损 → 下载（选 singles 库+歌单"国语精选"）→ 任务中心看到完成 → 飞牛歌单出现该曲。
2. **PC 专辑闭环**：专辑页搜"叶惠美" → 详情 → 下载整张 → 任务中心跟踪逐曲进度 → 完成后归档 → 结果页逐曲核对，失败曲一键重搜。
3. **榜单批量**：榜单 → 网易热歌榜 → 全表下载 → 任务中心跟踪。
4. **库维护**：媒体库 → 歌词回填 dry_run 预览 → 执行 → 结果清单。
5. **配置热改**：设置页粘贴 QQ cookies → 保存 → 无需重启，仪表盘 QQ 源转绿。
